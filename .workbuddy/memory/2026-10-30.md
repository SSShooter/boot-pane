## macOS 端任务启动适配（proctree/pty/prockill/portinfo/procinfo）

- 报错「创建进程树失败：进程树管理尚未实现」：proctree_unix / pty_unix 原为 M0/M1 空壳，本次全部实装。
- 新增 `internal/procinfo`：darwin 走 sysctl kern.proc.all + cgo proc_pid_rusage（枚举 + 单进程 CPU/RSS）；linux 走 /proc。`proctree.Usage` 与 `prockill` 树遍历共用。
- Group 接口新增 `Attach(pid)`：Windows 空操作；Unix 靠 Setsid 让 shell 自成组长（pgid == PID），pty 启动后由 manager 登记。
- pty_unix：/dev/ptmx + TIOCPTYGRANT/UNLK/GNAME（darwin）、TIOCGPTN/TIOCSPTLCK（linux）手写 ioctl，未引第三方库；shell 用 `$SHELL -l -c`（dash 不认 -l，按名字排除），`ensurePath` 兜底补 homebrew/go/用户 bin 目录（GUI 启动 PATH 只有 /usr/bin:/bin:/usr/sbin:/sbin）。
- **重要坑 1**：`ri_user_time` 单位是 Mach 绝对时间 tick 不是纳秒——与 wait4 rusage 交叉验证，比值 23.93 = Apple Silicon 24MHz 时基；必须 `mach_timebase_info` 换算，Intel 上 numer/denom=1 才恰好等于纳秒。
- **重要坑 2**：`zsh -l`（登录 shell）退出用 TCSADRAIN 恢复 tty，master 无人读时 shell 永远卡在退出路径 → `Wait` 挂死。变量隔离定位：直接 exec /bin/echo 正常、zsh -c 无 -l 正常、zsh -l 卡住、有 reader 正常、CPU 0。生产链路 pumpLogs 从启动就持续读没问题，但这是 pty.Start 的调用契约，已写入注释；测试里必须挂 drain。
- prockill_unix：procinfo 快照 + PPID 后序遍历（子前父后）+ 逐个 SIGKILL（ESRCH 跳过）；portinfo_unix：lsof -nP -iTCP -sTCP:LISTEN 解析（剥尾部 (LISTEN)），processName 走 procinfo。
- 测试：pty 5 例、proctree 4 例（清树/幂等/采样/未 Attach）、prockill 3 例、portinfo 2 例、procinfo 3 例（含单位验证）全过；GOOS=windows 交叉编译通过，Windows 语义对齐（Wait 正常退出只给码不带错，信号死亡才带错）。
- go build ./... 里 bootpane/build/ios 的 "function main is undeclared" 是既有 wails 模板问题（GOOS 未设 ios 时包内无 main），与本次无关。

## 修复 waitFor port 对 IPv6-only 服务误判「已失败」（m10c WXT 案例）

- 现象：m10c 的 wxt dev server（:3030）明明起来了，BootPane 却标「已失败」。实测：WXT 只监听 `[::1]:3030`（纯 IPv6），而 `waitPort` 只拨 `127.0.0.1` → 永远 connection refused → 超时；`Manager.fail` 只改状态不杀进程，所以服务还活着。
- 修复（两层）：
  - `internal/process/waitfor.go`：`waitPort` 改为每轮轮询同时拨 `127.0.0.1` 和 `[::1]`，任一成功即就绪。Node 生态只绑单栈很常见，修代码让所有已生成配置直接受益，不用重新生成。
  - `internal/config/prompt.go`：【就绪判定 waitFor】改为优先级引导——首选 log 类型（附可靠标记例：vite `ready in`、WXT `Started dev server`），端口只在真实读到时写，并注明探测已覆盖 IPv4/IPv6；输出示例的 web 任务从 port 改成 log 类型（显式 openUrl 优先级最高，不受影响）。文件头踩坑注释同步更新。
- 验证：`go test ./internal/config/` 通过；临时测试对真实 3030 IPv6-only WXT 服务 `waitPort` PASS（测试文件已删）。build/ios 报错与 ld macOS 版本 warning 均为既有问题。
- 用户须知：前端经 go:embed 打进二进制，重新 build 后重启 BootPane 才生效；改完后 m10c 现有配置重按「启动」即可正确判活。
