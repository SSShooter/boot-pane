# 2026-10-30

## 修复 macOS 顶部排版（交通灯遮内容、无品牌）

- 现象：macOS 下 `MacTitleBarHiddenInset` 的系统交通灯叠在侧栏搜索框上（顶部无让位），且 `InvisibleTitleBarHeight: 50` 的隐形拖拽区盖住搜索框/「+」按钮不可点；`customChrome` 仅 Windows 为 true，唯一的品牌位 TitleBar.svelte 在 macOS 不渲染。
- 修复：
  - `frontend/src/lib/chrome.ts`：新增 `onMac()`（environment.OS === "darwin"，UA 兜底 `/Macintosh/`）与导出 `macChrome = !isPreview && onMac()`。
  - `frontend/src/App.svelte`：`macChrome` 时渲染 `.titlebar.mac-titlebar`（复用 TitleBar 结构，仅品牌 + 拖拽区，不画窗口按钮），`.app` 加 `mac-inset` class。
  - `frontend/public/style.css`：新增 `--mac-inset-h: 50px`（注释要求与 main.go `Mac.InvisibleTitleBarHeight: 50` 保持一致）、`.app.mac-inset { grid-template-rows: var(--mac-inset-h) minmax(0,1fr) }`、`.mac-titlebar { height: var(--mac-inset-h) }`、`.mac-brand { padding-left: 84px }`（让开交通灯约 70px）。
- 验证：svelte-check 0 错误，vite build 通过。浏览器实测未做：chrome-devtools MCP 连接本地 Chrome 超时（调试端口未开），按约定停手；待用户 `wails dev` 或重跑 app 确认。

### 二轮修复：重启后无变化 → isPreview 误判

- 现象：用户重建二进制（14:00）后重启，界面无变化；截图右侧露出 `my-shop / D:\code\...`，正是 `devmock.ts` 的假数据 → macOS dev 窗口整个跑在预览模式。
- 根因：`api.ts` 的 `inWebView` 只认 Windows WebView2 的 `chrome.webview`；macOS WKWebView 没有该字段 → dev 下 `isPreview=true` → mock 数据 + `customChrome`/`macChrome` 全关。
- 修复：
  - `api.ts`：`inWebView` 增加 `!!window._wails` 兜底（Wails runtime 在业务脚本前同步挂载）。
  - `chrome.ts`：新增 `?mac=1` 调试参数，浏览器预览可强制渲染 macOS 顶部留白核对布局。
- 用户须知：前端是 `go:embed all:frontend/dist` 打进 Go 二进制的，改前端后必须重新 build，只重启不生效；`task dev` 则由 vite 热更新。
