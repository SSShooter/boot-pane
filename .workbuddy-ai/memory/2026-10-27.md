# 2026-10-27

## bootpane M0 落地

在 Wails3 脚手架（Go 1.26 + Svelte 5 + Vite）上搭出项目启动器的骨架。

### 架构决策（已与用户确认）

- **技术栈**：沿用 Wails3，不换 Tauri/Electron。核心是管理本地进程树，Go 最合适。
- **平台**：先只做 Windows，但平台差异全部收在 `internal/pty`（Session 接口）和
  `internal/proctree`（Group 接口）后面，用 build tag 分 `_windows.go` / `_unix.go`。
  业务层禁止出现 `runtime.GOOS`。后面补 mac/Linux 只加文件不改逻辑。
- **配置双层**：全局注册表 `%APPDATA%\bootpane\workspace.json`（有哪些项目、个人覆盖层）
  + 仓库内 `.bootpane.json`（怎么启动，进 git）。合并按 `task.id`，仓库优先，
  全局层补缺并标 `origin: "local"`。
- **Agent**：规则引擎 + LLM 一起做，但两者输出共用同一个校验器（命令里的 script 必须真实存在、
  cwd 必须存在、端口不撞），生成结果先出 diff 预览再落盘。
- **日志**：内存环形缓冲 + 可选落盘。必须节流（攒 50ms 或 32KB 批量推），否则 vite 启动瞬间
  会把 Wails 事件通道打满。

### 已完成

- `internal/config`：模型、双层合并、校验（缺命令 / 依赖不存在 / 依赖成环 / 端口冲突 /
  cwd 不存在）、原子写盘、首次运行 seed。7 个单测全过。
- `internal/{pty,proctree,process,discovery}`：接口 + 骨架，M1/M4 填充实现。
- `app_services.go`：ConfigService / ProcessService 暴露给前端。
- 前端：侧边栏项目列表 + 任务卡片矩阵 + 校验 banner + 空态/错误态 + toast。
- `frontend/src/lib/api.ts` 做了 API 抽象：非 WebView2 环境（纯浏览器跑 vite dev）
  自动走 `devmock.ts` 的假数据，方便只调 UI。

### 已知问题

**Wails v3.0.0 在本机 WebView2 155.0.4283.62 下渲染进程崩溃循环。**
症状：`webview2: process failed (kind=0); recovery attempt 1 of 3` 反复出现，
每 3 秒重建 controller，窗口空白。试过 `--disable-gpu`、`--no-sandbox`、
`--disable-features=RendererCodeIntegrity`、`--in-process-gpu` 均无效。
v3.0.0 已是 Wails 最新发布版，无更新版本可升。
待查：可能是 Wails 封装的 WebView2Loader 与新 Runtime 不兼容，或本机远程会话环境限制。
**注意**：这是 Wails 运行时问题，与业务代码无关——同一份前端产物在 Edge headless 里
渲染完全正常（见 `.workbuddy-ai/preview/m0-main.png`）。
